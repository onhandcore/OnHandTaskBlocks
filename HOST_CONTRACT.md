# Public Host contract

ABI: onhand.taskblocks.host.v1. Entry taskblocks.invoke.invoke(surface,payload); taskblocks.public exports PublicHostSurface(root,task_run_id=None) and invoke. Root must equal this actual installation, task_run_id must be null. The Host interpreter must be CPython 3.12 x64. Host and spawned processes use the same TASKBLOCKS_STATE_DIR (default installed-root/state). TASKBLOCKS_PORT defaults to 8765; bind loopback only. A registered installation uses its actual reviewed Thoroughfare binding; this directory alone is not registered.

## Launch and GUI handoff

Launch payload has contract_version, operation=launch, optional prompt, delivery_id, port. Unknown keys/version/operation fail closed. Port is an integer 1024..65535. Nonempty prompt requires stable delivery_id; immutable retries preserve exact text/ID/Host. No prompt opens the choice/recovery entry. Text is not put in a URL. CLI supports `python -B -m taskblocks.launch`, or --prompt-file and --delivery-id; it never Fires. Windows launch uses the existing Native supervisor and loopback backend.

DIRECT desktop launch retains the existing supervisor path. UNKNOWN desktop stops before process creation. ISOLATED returns HOST_GUI_ACTION_REQUIRED with gui_action and required_host_action=CLAIM_VALIDATE_EXECUTE_ONCE_THEN_REPORT. The original Host validates exact original Host/product/state/runtime/port, descriptor, Python and EXE hashes and request_digest (SHA256 of sorted compact UTF-8 JSON excluding request_digest). It calls operation=gui_claim with request_id, request_digest, optional port; execute=true is single use. Only then use an existing authorized app-launch tool with exact gui_action.tool_input once. No guessing argv, alternate launcher or elevation. Replay execute=false never permits execution.

Report gui_result with same correlation, outcome SUCCEEDED/DEFINITE_FAILURE/DENIED/UNKNOWN and nonempty actual reason. A GUI-tool observation does not prove product startup; reconcile exact product ready/answer/PID/HTTP receipts. Missing/uncertain side effects remain UNKNOWN without retry. If no authorized exact app-launch tool exists, report the actual denial/failure and stop. Retain current-session facts; never another Host's attachment. Native bootstrap records are retained in user state for correlation.

The original Host MUST enter the returned host_reception bounded tool wait in the same turn and continue through TIMEOUT, input, confirmation, Fire and Child result boundaries until BUSINESS_FINALIZED or explicit Native session exit. STARTED/TIMEOUT alone does not authorize ending standby. There is no scheduler that resumes an ended Host turn. Business finalization leaves Native open; actual Native FormClosing closes the launch.

## Tasks, delivery, concurrency and recovery

TASK_INPUT requires original Host to read exact text, understand it and call v2.submit_plan with real steps/dependencies or explicit failure. Wait for fresh user plan confirmation before parent_ack/delivery/Fire. TASK_CONFIRMATION/parent_ack is not Fire. FIRE remains SUBMITTED until actual independent ForkJoin binding succeeds. Host owns task creation, public receipts, bounded delivery Probe and Join under current ForkJoin contracts. host.FormalClient uses only supplied current-session governance/attachment/socket facts and existing public transport. No fallback after STOP.

Read full capsules in emission order through delivery.read_next before marking read. Copy/sign/read is not execution success. Manual handoff uses the exact official manual_prompt and full JSON; do not persist bearer/recovery secrets in ordinary reports or capsules. UNKNOWN creation never authorizes another create. Probe lifetime is per explicit delivery session/template closure, not a resident model scheduler.

Sequential submission is the untouched default. Explicit salvo fills eligible selected steps in order with integer capacity 2..20, shares manual/automatic capacity and preserves unresolved reservations. Settings never Fire. Formal ForkJoin admission controls actual Host capacity. Host drains eligible Fire without waiting for earlier Child RESULT, subject to capacity, dependencies and exact artifact selections. Failure pauses auto; pause is not STOP. Recovery/page opening pauses auto and preserves selections. Preserve STOP priority, emission order, frozen per-Fire preferences and submission_preferences during recovery.

Recover only from explicitly selected accessible records. Recovery does not transfer old Group management rights. COMPRESS uses a formal Child with bounded manifest and verified real RESULT/Join, not a request receipt. Repair requires lawful new work order/wake/binding, verified quiescence and protected independent artifact bytes before adopt_repair_round. Never reopen historical RESULT or apply old callbacks to a new round.

## Completion and separate lifetimes

At actual RESULT/sync/selection boundaries and bounded waits inspect terminal readiness. AUTO_FINALIZE_REQUIRED requires handling every pending control through host.resolve_control with real evidence before host.auto_finalize. Verify official RESULT identity/digest/equality, cessation/quiescence, Join, unhandled events, Host acceptance, selected artifact versions/bytes and actual deliverables. Supply an idempotent finalize_administration callback performing only existing lawful ForkJoin/Drudge closure, returning real public evidence paths/hashes. The product does not invent administrative success. Failed/stopped/partial results require truthful exceptions.

host.cancel_unstarted settles only never-fired work after real Host judgment with reason/evidence, never a created or uncertain Child; it cannot yield overall SUCCESS. Completion persists one digested receipt; identical replay does not repeat administration. State contention has bounded retry, never delete a live lock. Host reads host.completion and delivers its concise actual summary once. BUSINESS_FINALIZED carries continue_same_turn=false; stop standby then. Native completion display uses that same verified receipt and rechecks artifact bytes.

Normal Native close does not terminate independent Child work. First use lawful Host STOP/Join/administrative closure as needed. Native/supervisor/owned HTTP exit is separate from business and registration lifecycle. Formal removal uses current published lifecycle with actual revisions and verified quiescence; no manual central-state writes. Program deletion is user/Host-owned. Retain intentional user work-order data separately.

Host HTTP mutations require externally supplied TASKBLOCKS_HOST_TOKEN, never exposed to browser. Direct Python operations stay under Host filesystem governance and cooperative local trust. Do not use V1 raw result APIs to assert V2 success. User history records accessible real text/outcomes only and is not execution authority. No model pre-output hook or hidden-reasoning export is promised.
